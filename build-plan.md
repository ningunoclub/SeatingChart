# Seating Chart — Build Plan

A lightweight, fully offline macOS app that generates random seating charts for school classes, with a visual room editor, per-class constraints, fullscreen presentation mode, PDF export, and a random name picker with an always-on-top overlay window. UI in English and German.

**Status: implemented.** All seven milestones are built; `swift build` and the
test suite are green, and `scripts/make-app.sh` produces a signed `Seating Chart.app`.

---

## 1. Tech stack & project decisions

| Decision | Choice | Rationale |
|---|---|---|
| Language / UI | Swift 5.10+, SwiftUI | Native macOS look, lightweight, no runtime deps |
| Deployment target | macOS 14.0 (Sonoma) | Modern SwiftUI APIs (`ImageRenderer`, `NavigationSplitView`, `Observable`) |
| Build system | Swift Package Manager (`Package.swift`), executable target | Builds from terminal with `swift build`, no `.xcodeproj` required |
| App packaging | `scripts/make-app.sh` wraps the release binary + resources into `Seating Chart.app` | Double-clickable app without Xcode |
| Persistence | JSON via `Codable` in `~/Library/Application Support/SeatingChart/` | Local, offline, human-readable, trivially backupable |
| Student photos | Image files copied into `.../SeatingChart/Images/<studentID>.<ext>` | Keeps JSON small; files referenced by student ID |
| Localization | `Localizable.strings` in `en.lproj` / `de.lproj`, `defaultLocalization: "en"` | Follows system language automatically |
| Third-party libraries | None | Lightweight, zero supply-chain surface |
| Architecture | MV pattern: `@Observable` app store + value-type models; solver as pure functions | Small app; testable core |
| Tests | `swift test` unit tests for the solver + persistence round-trip | The solver is the only algorithmically risky part |

## 3. Data model (specific)

All models are `Codable`, `Identifiable`, `Hashable` value types with `UUID` ids.

### Student
```swift
struct Student {
    var id: UUID
    var firstName: String
    var photoFileName: String?   // file inside Images/, nil = show initials avatar
    var gender: Gender           // .male | .female | .unspecified — used only by §6.5
}
```

### SchoolClass
```swift
struct SchoolClass {
    var id: UUID
    var name: String             // e.g. "5a"
    var students: [Student]
    var constraints: [Constraint]
}
```

### Room & Desk
```swift
struct Room {
    var id: UUID
    var name: String             // e.g. "Zimmer 204"
    var desks: [Desk]
}

struct Desk {
    var id: UUID
    var gridX: Int               // column on the editor grid (0-based, left → right)
    var gridY: Int               // grid row (0-based); 0 = closest to blackboard
    var isDisabled: Bool         // empty-seat control: never assigned
}
```

**Row semantics.** The blackboard is always drawn at the top of the canvas. A desk's
*classroom row* is derived, not stored: collect the distinct `gridY` values of enabled
desks, sort ascending; row number = index + 1. So row 1 is always the front row, even
if the teacher leaves grid rows empty for aisles.

**Seat numbers.** Derived deterministically per room: sort desks by (`gridY`, `gridX`),
number 1…n. Disabled desks keep their number (displayed grayed out) so the numbering
stays stable when toggling.

### Constraint
```swift
enum Constraint {
    case keepApart(a: UUID, b: UUID)            // student IDs, unordered pair
    case rowPin(student: UUID, row: Int)        // classroom row, portable across rooms
    case seatPin(student: UUID, roomID: UUID, deskID: UUID)  // one exact desk in one room
}
```
Stored on the class. `seatPin` carries the room ID so the same class can have different
seat pins in different rooms; pins for other rooms are ignored during generation.
Constraints referencing a deleted student/room/desk are pruned on load and on delete.

### SeatingChart (result)
```swift
struct SeatingChart {
    var id: UUID
    var classID: UUID
    var roomID: UUID
    var mode: GenerationMode          // .trueRandom or .constrained(adjacency:)
    var assignment: [UUID: UUID]      // deskID → studentID
    var generatedAt: Date
}

enum AdjacencyMode { case relaxed, strict }   // relaxed = sides only; strict = + front/behind
```
The app persists the most recent chart per (class, room) pair so the current chart
survives restarts.

### Adjacency (computed, not stored)
Two enabled desks are adjacent when:
- **Side neighbors** (always): same `gridY` and `|gridX₁ − gridX₂| == 1`.
- **Front/behind** (strict mode only): same `gridX` and `|gridY₁ − gridY₂| == 1`.

Gaps break adjacency: desks at gridX 0 and 2 with an empty column between them are
*not* neighbors — this is how the editor models separated desk pairs and aisles.

## 4. Generator engine

Pure function, no UI dependencies:

```swift
func generate(class: SchoolClass, room: Room, mode: GenerationMode,
              rng: inout RandomNumberGenerator) throws -> SeatingChart
```

### Preconditions (typed errors, shown as localized alerts)
- `notEnoughSeats(students: Int, seats: Int)` — enabled desks < student count.
- `invalidPin(...)` — row pin references a row the room doesn't have; seat pin
  references a disabled/missing desk; two students pinned to the same desk.
- `unsatisfiable` — backtracking exhausted (see below).

### True random mode
Shuffle students, deal onto enabled desks in seat-number order. Ignores keep-apart
and pins entirely. If seats > students, leftover desks stay empty.

### Constrained mode — randomized backtracking
1. **Apply seat pins** for this room, then **row pins**: for each row-pinned student
   (random order), pick a random free enabled desk in that classroom row.
2. Build the adjacency map for the chosen `AdjacencyMode`.
3. **Backtracking:** shuffle unplaced students and free desks. Assign students one at a
   time (most-constrained student first — the one appearing in the most keep-apart
   pairs — to fail fast); for each, try free desks in random order, rejecting any desk
   adjacent to an already-seated conflicting student. Backtrack on dead ends.
4. **Restart cap:** at most 200 restarts with fresh shuffles, and a global step budget
   (~200k assignment attempts) so an unsatisfiable setup returns `.unsatisfiable` in
   well under a second instead of hanging. The error message names one violated
   keep-apart pair when identifiable.
5. Randomization guarantees a *different-feeling* chart each run; a "Generate again"
   button simply reruns with a new seed.

Class sizes are ≤ ~35, so backtracking is more than fast enough; no need for anything
fancier.

## 5. Persistence

Single JSON document + images folder:

```
~/Library/Application Support/SeatingChart/
├── data.json        { schemaVersion: 1, classes: [...], rooms: [...], charts: [...] }
└── Images/
    └── <studentUUID>.jpg|png|heic
```

- `AppStore` loads on launch, autosaves (debounced ~1 s) on every mutation, and saves
  on app termination.
- Atomic writes (`.atomic`) so a crash never corrupts the file.
- `schemaVersion` field from day one for future migrations.
- Adding a photo: `NSOpenPanel` (images only) → file is **copied** into `Images/` named
  by student ID (existing photo replaced); removing a student deletes its image.
- Deleting a class/room prunes dependent constraints and charts.

- Before a destructive import, `data.json` is copied to
  `data-backup-<timestamp>.json` beside it — the app has no undo.

No iCloud, no network, no analytics — nothing leaves the machine.

### 5.1 Import & export (`.seatingchart`)

One self-contained file carries selected classes, rooms, generated charts **and
student photos**, so a class can be handed to a colleague or a whole library
moved to another Mac.

- **Format:** a single JSON document; `JSONEncoder` base64s the photo `Data`
  inline. No zip, because Foundation cannot unzip and the project takes no
  dependencies — and it keeps the file inspectable, like `data.json`.
  `format` magic string plus separate `bundleSchemaVersion` and
  `dataSchemaVersion`; a newer file is refused outright, never partially read.
- **Photos** are re-encoded on export via ImageIO to JPEG, longest side 1200 px,
  quality 0.85 — measured at 18.5 MB of PNG → 3.8 MB. Originals untouched.
  Transparency is flattened onto white, since JPEG has no alpha.
- **Export:** a sheet of per-class and per-room checkboxes plus
  "include photos" / "include charts". Reachable from File ▸ Export data… (⇧⌘E)
  or a sidebar right-click for one item.
- **Import:** File ▸ Import data… (⇧⌘I), the sidebar `+` menu, or double-clicking
  the file in Finder. A summary sheet offers **Add as copies** (fresh ids,
  nothing existing is touched) or **Replace matching items** (same-id overwrite,
  the backup-restore mode), and warns up front about fixed seats that cannot
  survive because their room is not in the file.
- All id remapping lives in `BundleTransfer`, a pure function over `DataFile`
  with no UI or I/O, so the risky part is unit-tested on its own.

## 6. UI specification

`NavigationSplitView` with a sidebar of three sections. German strings shown as (DE).

### 6.1 Classes (DE: Klassen)
- Sidebar lists classes; +/− to add/delete (delete confirms).
- **Class editor** (detail):
  - Editable class name.
  - Student table: photo thumbnail (or colored initials circle), first name (inline
    editable), row-pin badge if pinned.
  - Add students: text field where **pasting multiple lines adds one student per
    line**; single names via return key.
  - Per-student context menu / buttons: set photo…, remove photo, pin to row (number
    picker), remove pin, delete student.
  - **Constraints section** below the table:
    - Keep-apart list: each entry "Anna ↔ Ben" with delete; "Add pair" popover with
      two student pickers (same student twice rejected; duplicate pairs rejected).
    - Seat pins listed read-only here ("Anna → Zimmer 204, seat 3") with delete;
      *created* in the chart view (right-click a desk → pin student), because they
      need a room context.

### 6.2 Rooms (DE: Räume)
- Sidebar lists rooms; +/− to add/delete.
- **Room editor** (detail): visual canvas.
  - **Blackboard** rendered as a labeled dark bar across the top ("Blackboard" /
    DE "Tafel") — the fixed orientation reference.
  - Grid of ~44 pt cells. Desks drawn as rounded rectangles showing their derived
    seat number; disabled desks hatched/grayed.
  - **Interactions:**
    - Click an empty cell → add desk.
    - Drag a desk → move (snaps to grid; dropping on an occupied cell reverts).
    - Right-click desk → toggle disabled / delete desk.
    - Row labels along the left edge ("Row 1", "Row 2"… / DE "Reihe") computed live
      from the current layout.
  - **Quick setup** toolbar button → sheet: rows (1–10), seats per row (1–12),
    optional "aisle after seat N" (inserts an empty grid column); *replaces* the
    current layout after confirmation. This covers "configure how many seats per
    row"; irregular rows are then edited by clicking/dragging.
  - Desk count + enabled-seat count shown in the toolbar.

### 6.3 Seating chart (DE: Sitzplan)
- **Controls bar:** class picker, room picker, mode picker
  (True random / DE "Zufällig" · With constraints / DE "Mit Regeln"),
  adjacency toggle (Sides only / Also front & behind — visible only in constrained
  mode), **Generate** button (⌘R), Generate-again arrow.
- Capacity hint under the pickers: "24 students · 26 seats". Error alerts for the
  typed generator failures.
- **Chart display:** the room layout (blackboard on top) with each occupied desk
  showing photo (or initials), first name, seat number. Empty enabled desks show just
  the number; disabled desks grayed. Right-click a seated/empty desk → "Pin <student>
  here" / "Remove pin" (creates/removes `seatPin`).
- **Toolbar actions:**
  - **Present** (⌘⇧P): opens a second window, fullscreen-capable, black background,
    auto-scaled layout with large names + photos — for beamer/AirPlay. Esc closes.
    Live-updates if a new chart is generated while open.
  - **Export PDF** (⌘E): `ImageRenderer` renders a print-styled (white background,
    black text, header "Class 5a — Zimmer 204 — 2026-08-18") A4-landscape one-pager;
    `NSSavePanel` to choose destination.
  - **Print** uses the same rendering via `NSPrintOperation`.

### 6.4 Name picker (DE: Namen ziehen)

A second, independent use of the same class lists: calling on a random student.
Its own sidebar tab, below Seating chart. Its class selection and draw round are
deliberately separate from the chart's, so picking names never disturbs a chart.

- **Controls bar:** class picker, display-mode segmented picker
  (Name / Photo / Both), **Pick a name** button (⌘⌥R, also Return in the tab),
  a "No repeats until everyone has had a turn" toggle with an "7 of 24 picked"
  counter and a **Start over** link.
- **Draw:** without replacement by default — everyone gets a turn before anyone
  repeats, and the round restarts itself once the class is exhausted. Students
  added mid-round join the pool; deleted ones drop out. The logic is pure
  (`NameDraw`) and unit-tested with a seeded `SplitMix64`, as the solver is.
- **Reveal:** names flick past for ~0.8 s on a lengthening interval and settle on
  the winner. The model — not either view — owns `displayedStudentID`, so the tab
  preview and the overlay animate in step.
- **Overlay window** (⌘⌥N, or the toolbar toggle): a small resizable `NSPanel`
  meant to be dragged over a slideshow on a second monitor.
  - `level = .screenSaver`, since `.floating` sits *below* a running PowerPoint
    slideshow — the usual reason overlays get covered.
  - `.nonactivatingPanel` and `canBecomeKey == false`: it can be dragged and
    resized without taking the keyboard away from the presentation.
  - `hidesOnDeactivate = false`, or NSPanel hides itself exactly when it is
    needed. `.canJoinAllSpaces` + `.fullScreenAuxiliary` for fullscreen spaces.
  - Display only — every control stays in the app window.
  - Hidden with `orderOut` and the panel kept alive, so unhiding restores the
    position; `setFrameAutosaveName` carries it across launches, with a fallback
    to the main screen when the saved frame's monitor is gone.
- Display mode and the repeats toggle persist in `UserDefaults` (`namePicker.*`),
  not in `data.json` — they are UI preferences, not document content.

### 6.5 Auto grouping (DE: Gruppen bilden)

A third use of the same class lists: splitting the class into teams. Its own sidebar tab
below Name picker, with its own class selection, again so grouping never disturbs a chart.

- **Controls bar:** class picker; a "Number of groups / Max people per group" segmented
  picker with one stepper (the mock's "set either one" pair — as a segmented picker the two
  cannot be left contradicting each other); a per-group gender quota as two steppers
  (`0 / 0` = no quota); a "Pick representatives" toggle; a **Team names** button; and a live
  hint reading "24 students → 4 groups · 11 male · 11 female · 2 not specified".
- **Draw:** one shuffled pool per gender, dealt pool by pool into whichever group is
  currently smallest. That alone keeps both the sizes (within one of each other) and the
  genders even, with no balancing pass. An active quota is dealt first; a quota the class
  cannot fill is *not* an error — the shortfall is reported in orange and the draw seats
  everyone anyway. The logic is pure (`GroupDraw`) and unit-tested with a seeded
  `SplitMix64`, as the solver and the name draw are.
- **Team names:** an editable list in a sheet, seeded from the current group count. Blank
  entries are dropped; any group past the end of the list falls back to "Group 1, 2, 3…".
  Editing the names renames the groups already on screen rather than forcing a re-roll.
- **Overlay window** (⌘⌥U, or the toolbar toggle): the same `NSPanel` as §6.4's, with its own
  autosave name and a larger default size, showing a grid of team cards — representatives
  starred. Every metric is derived from the frame, so the same view is the in-app preview.
- **Groups are session-only** — a live draw, like the picker's round, not document content.
  What lasts is the **PDF export** (A4 portrait, one card per group), for when a grouping has
  to outlive the lesson.
- Settings (sizing, quota, representatives, team names) persist in `UserDefaults`
  (`grouping.*`). `Student.gender` is document content and lives in `data.json`; it decodes
  as `.unspecified` when absent, so files written before this feature open unchanged and
  `schemaVersion` stays at 1.

### 6.6 General
- All strings localized EN + DE via `Localizable.strings`; language follows the
  system (`defaultLocalization: en`).
- Undo is out of scope for v1 (destructive actions confirm instead).
- Window title reflects selection; sensible minimum window size (~1000×700).

## 7. Build & run

```bash
swift build                    # debug build
scripts/test.sh                # solver + persistence + export tests
swift run SeatingChart         # run from terminal
scripts/make-icon.sh           # icon/AppIcon.png → icon/AppIcon.icns
scripts/make-app.sh            # release build → ./Seating Chart.app (double-clickable)
```

Tests use swift-testing. Use `scripts/test.sh` rather than `swift test` directly:
without a full Xcode, swift-testing lives in the Command Line Tools developer
directory and SwiftPM's generated test runner does not add it to its framework
search path — a bare `swift test` then builds fine but silently runs zero tests.
The script passes the path; with Xcode installed, plain `swift test` also works.

`make-app.sh`: `swift build -c release`, assemble
`Seating Chart.app/Contents/{MacOS,Resources}`, copy binary + SPM resource bundle,
write `Info.plist` (bundle ID `com.ningunosound.seatingchart`, `LSMinimumSystemVersion`
14.0, app category Education), `codesign --force --sign -` (ad-hoc) so Gatekeeper is
happy locally.
